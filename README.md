# 🍕 จับคู่อาหาร (Food Memory Match Game)

เกมจับคู่ภาพความจำ (Memory Matching Game) ธีมอาหาร เขียนด้วย HTML, CSS และ JavaScript ล้วน ไม่ใช้ไลบรารีหรือเฟรมเวิร์กใดๆ ไฟล์เดียวจบ เปิดเล่นได้ทันทีในเบราว์เซอร์

## 🎮 เล่นเกม

เปิดไฟล์ `food-memory-game.html` ด้วยเบราว์เซอร์ หรือถ้า deploy ด้วย GitHub Pages แล้ว ให้เข้าลิงก์เว็บไซต์ของ repo นี้ได้เลย

## 📋 วิธีเล่น

1. กระดานมีการ์ดคว่ำอยู่ 20 ใบ (อาหาร 10 ชนิด ชนิดละ 2 ใบ)
2. คลิก/แตะการ์ด 2 ใบเพื่อพลิกดู
3. ถ้าอาหารตรงกัน → การ์ดจะค้างเปิดไว้ (นับเป็น 1 คู่)
4. ถ้าไม่ตรงกัน → การ์ดจะคว่ำกลับให้ลองใหม่
5. จับให้ครบ 10 คู่เพื่อชนะเกม พร้อมดูจำนวนครั้งที่ใช้ทั้งหมด

## 🧱 โครงสร้างไฟล์

ไฟล์เดียว (`food-memory-game.html`) แบ่งเป็น 3 ส่วนในตัว:

| ส่วน | หน้าที่ |
|---|---|
| **HTML** | โครงหน้าเว็บ: หัวข้อ, HUD (แถบคะแนน), กระดานเกม, กล่องแจ้งชนะ |
| **CSS** | ดีไซน์ทั้งหมด: สี ฟอนต์ และแอนิเมชันพลิกการ์ดแบบ 3D |
| **JavaScript** | ตรรกะเกมทั้งหมด: สุ่มการ์ด ตรวจจับคู่ นับคะแนน |

## 🖥️ ส่วนประกอบหน้าจอ (HUD)

```html
<div class="pill">🔁 <span id="moves">0</span> ครั้ง</div>
<div class="pill">✅ <span id="matches">0</span>/10</div>
<button id="resetBtn">เริ่มใหม่</button>
```

- `moves` — นับจำนวนครั้งที่พลิกการ์ดครบคู่ (พลิก 2 ใบ = 1 ครั้ง)
- `matches` — นับจำนวนคู่ที่จับถูกแล้ว จากทั้งหมด 10 คู่
- ปุ่ม **เริ่มใหม่** เรียกฟังก์ชัน `startGame()` เพื่อสุ่มกระดานใหม่ทั้งหมด

## 🔀 การสุ่มและสร้างการ์ด

```javascript
var FOODS = ["🍕","🍔","🌭","🍟","🍩","🍦","🍉","🍇","🍓","🍎"];

function buildDeck(){
  var pairs = FOODS.concat(FOODS);   // อาหาร 10 ชนิด x 2 = 20 ใบ
  shuffle(pairs);                     // สลับตำแหน่งแบบสุ่ม
  return pairs.map(function(food, idx){
    return { id: idx, food: food, matched: false };
  });
}
```

- เริ่มจากอาหาร 10 ชนิด แล้วใช้ `.concat(FOODS)` ทำให้ได้ 20 ชิ้น (แต่ละชนิดมี 2 ใบ)
- `shuffle()` ใช้เทคนิค **Fisher-Yates shuffle** — วนจากท้ายอาร์เรย์มาหน้า สลับตำแหน่งกับดัชนีสุ่ม ทำให้กระจายอย่างเท่าเทียมจริงๆ ต่างจาก `sort(() => Math.random() - 0.5)` ที่คนมักเขียนผิดและกระจายไม่เท่ากันจริง
- แต่ละการ์ดเป็น object เก็บ `id` (ตำแหน่งเฉพาะ), `food` (อีโมจิ), `matched` (จับคู่แล้วหรือยัง)

## 🃏 แอนิเมชันพลิกการ์ด (CSS 3D Flip)

การ์ดแต่ละใบมี 2 หน้าซ้อนกัน:

```css
.card-inner{ transform-style: preserve-3d; transition: transform .45s; }
.card.flipped .card-inner{ transform: rotateY(180deg); }
.face.back{ /* หน้าคว่ำ มี "?" */ }
.face.front{
  transform: rotateY(180deg);   /* พลิกกลับด้านไว้ล่วงหน้า */
  backface-visibility: hidden;  /* ซ่อนด้านหลังเวลาไม่หัน */
}
```

พอใส่คลาส `.flipped` ให้การ์ด → `.card-inner` จะหมุน 180 องศา → หน้า "back" (มี `?`) หันไปด้านหลัง ส่วนหน้า "front" (มีรูปอาหาร) หันมาข้างหน้าแทน เกิดเป็นเอฟเฟกต์พลิกไพ่จริงๆ

## 🧠 ตรรกะการจับคู่ (หัวใจของเกม)

```javascript
function handleFlip(id, el){
  if(lock) return;                    // กำลังเช็คคู่อยู่ ห้ามพลิกเพิ่ม
  var card = deck.find(c => c.id === id);
  if(!card || card.matched) return;   // จับคู่ไปแล้ว พลิกซ้ำไม่ได้

  el.classList.add('flipped');
  flipped.push({ id, el, food: card.food });

  if(flipped.length === 2){           // พลิกครบ 2 ใบแล้ว
    moves++;
    lock = true;                      // ล็อกไม่ให้พลิกใบที่ 3 ระหว่างเช็ค

    if(a.food === b.food){            // ตรงกัน
      setTimeout(() => {
        a.el.classList.add('matched');
        b.el.classList.add('matched');
        matches++;
      }, 350);
    } else {                          // ไม่ตรงกัน
      setTimeout(() => {
        a.el.classList.remove('flipped');
        b.el.classList.remove('flipped');
      }, 800);
    }
  }
}
```

**ทำไมต้องมี `lock`?**
ป้องกันผู้เล่นคลิกรัวๆ พลิกการ์ดใบที่ 3 ขณะระบบกำลังเช็คคู่ที่ 1-2 อยู่ ถ้าไม่ล็อกไว้ ตรรกะเทียบคู่จะสับสนและเกมจะพัง

**ทำไมต้องมี `setTimeout`?**
ให้ผู้เล่นมีเวลา "เห็น" การ์ดทั้ง 2 ใบก่อนที่ระบบจะจับคู่ถาวร (350ms) หรือพลิกกลับคว่ำ (800ms — นานกว่าเพื่อให้เวลาจำภาพก่อนคว่ำ)

if(matches === FOODS.length){   // ครบ 10 คู่

## ♿ การเข้าถึง (Accessibility)

- ทุกการ์ดมี `role="button"` และ `tabindex="0"` — กด **Tab** เลือกได้ กด **Enter/Space** พลิกได้ ไม่ต้องใช้เมาส์อย่างเดียว
- `aria-label` เปลี่ยนข้อความตามสถานะการ์ด (คว่ำอยู่ / เป็นอาหารอะไร) เพื่อให้โปรแกรมอ่านหน้าจอ (screen reader) เข้าใจ
- รองรับ `prefers-reduced-motion` — ถ้าผู้ใช้ตั้งค่าเครื่องให้ลดแอนิเมชัน เกมจะตัดเอฟเฟกต์หมุน/pop ออกให้อัตโนมัติ
- รองรับ responsive: ปรับจำนวนคอลัมน์กระดานตามขนาดหน้าจอ (4 คอลัมน์บนมือถือ, 5 คอลัมน์บนจอกว้างขึ้น)

## 🍎 ทำไมใช้อีโมจิแทนรูปภาพจริง

ใช้อีโมจิ (Unicode) แทนการโหลดรูปภาพจากอินเทอร์เน็ต เพราะ:

- ไม่มีปัญหาเรื่องลิขสิทธิ์รูปภาพ
- โหลดเร็ว ไม่ต้องพึ่งอินเทอร์เน็ต ไฟล์เดียวจบ
- แสดงผลเหมือนกันทุกอุปกรณ์ (มือถือ/คอม) เพราะเป็นฟอนต์ของระบบเอง
